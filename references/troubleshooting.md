# 故障定位与停止条件

| 现象 | 可以得出的结论 | 下一步 |
|---|---|---|
| Missing terminal environment variables | 当前执行进程没有必填配置 | 让用户在终端 `source scripts/configure.sh`；确认实际调用进程继承了变量。不要读取其他账号的密钥 |
| URL 校验失败 | 不是可接受的 HTTPS API 基础 URL | 对照服务商 API 文档；不要关闭 TLS，不要猜测私人地址 |
| `doctor` 通过但实际调用失败 | 本地语法正确，不代表网络或权限正确 | 用户同意后 `doctor --list-models`；仍不能把列表当作生图支持证据 |
| HTTP 401 / 403 | 认证或访问被拒绝 | 让用户自行核对 Key、权限、IP 策略，不在聊天贴 Key |
| HTTP 3xx | 服务要求重定向，本工具已拒绝跟随 | 请用户从可信文档确认最终 API 基础 URL，避免认证头泄漏 |
| HTTP 400 / unsupported model | 当前请求组合未被上游接受 | 报告模型和脱敏错误；先确认账号支持，再经用户同意换主模型 |
| HTTP 404 | API 路径或工具可能不支持 | 核对 BASE_URL 是否正确包含 `/v1` 等前缀；不能直接改用未经确认的端点 |
| HTTP 429 / 503 / compatible accounts | 限流或中转账号池不可用等 | 不反复重试；最终错误可能掩盖最初的上游 400。需要运营方查看同一请求的日志 |
| 已进入 generating 后超时/断流 | 不能确定图片是否已经在上游生成 | 不自动重试，先查看运营方用量或账单 |
| completed 没有 PNG | 文本完成不等于图片生成成功 | 检查图片工具声明、tool_choice、桥接策略；报告而非伪造图片 |
| 实际尺寸/质量不同 | 中转未严格兑现请求参数 | 以实际 PNG 和工具返回值为准；不要静默缩放或宣称请求质量已实现 |
| 图片成功但没有单独图片 usage | 成功证据不等于完整计费证据 | 对齐 response_id / request_id 查询账单，不猜扣哪个额度池 |

## 两个模型字段

```text
POST {BASE_URL}/responses
├─ model: gpt-5.5                         主模型，理解请求/调用工具
└─ tools: [{type: image_generation,
           model: gpt-image-2}]           图片生成模型
```

主模型可以替换为服务支持且账号可用的其他模型。成功调用一个名字，不足以证明中转没有做别名映射或内部模型替换。CC Switch 不是这个独立 CLI 的依赖。

`/responses` 的图片工具桥接和独立 `/images/generations` 的内部实现可能不同。前者成功不能证明后者已修好；不要擅自修改桥接开关或默认模型。

## 向运营方提供什么

提供脱敏错误、请求时间、请求的模型名、request_id / response_id、实际尺寸/质量差异。JSON 包含提示词，应先人工确认是否适合分享。**不提供 Key、完整环境变量、认证头或私人输入文件。**
